# 分红、资产净值与回撤

[返回首页](../README.md) · [数据模型](schema-v2.md) · [MCP 接入](使用与部署.md#mcp-接入)

投资页面回答证券赚了多少；资产走势回答所有已记录账户如何变化。两者分别计算，避免将账户现金或分红加两遍。

## 已到账分红与证券收益

Agent 使用 `add_cash_entry` 记录实际净到账金额，类型为 `dividend`，填写原券商账户和 `symbol`。当前证券使用 USD；收益归属要求同账户、同标的已有买入记录。即使股票已清仓，之后到账的分红仍可计入。

```text
证券总回报金额 = 未实现盈亏 + 已实现盈亏 + 已归属净分红
证券 XIRR 现金流 = 含手续费的买入支出、卖出净收入、已归属净分红、期末持仓价值
```

XIRR 始终按美元及实际日期计算，少于 90 天或没有唯一有效解时展示原因。分红明细在“投资 → 投入与收益”中按标的及账户展开，包含已清仓标的、实际到账日期和冲销关联。证券历史收益曲线包含截至该日的已到账分红，市值曲线仍只显示证券持仓。

记录分红同时增加账户现金，净资产因此增加一次；证券总回报只是分析指标，不会再写入现金或累加到净资产。金额填写扣除已扣缴税款后的实际净到账，不将同一税费再扣一遍。分红再投资需另行记录真实买入、费用与结算。

缺少标的、账户归属不成立或非 USD 分红不会被悄悄略过：已归属金额仍可核对，总回报和 XIRR 暂不可计算，并列明问题流水。冲销在所填冲销日期反向影响余额和收益；问题金额全部冲销后，之后的统计可恢复，历史未解决日期仍保留缺口。

## 让 Agent 关联实际结算

现金流水中的 `deposit`、`withdraw` 可能是外部入出金，也可能是证券成交的交割款。应用不能凭相同日期或金额猜测用途，因此使用 `trade_settlements` 显式关联。

1. 调用 `list_accounts`、`list_trades`、`list_cash_entries(account_id)`，核对成交与真实资金变动。
2. 若真实结算尚未记录，使用 `add_cash_entry` 记录实际日期、原币及净金额。交易记录本身不会生成现金流水。
3. 读取账户最新 `revision`，调用 `set_trade_settlement(trade_id, cash_entry_id, expected_revision, idempotency_key, dry_run=true)` 预览，再以 `dry_run=false` 提交。
4. 调用 `get_asset_history(period="all", currency="CNY")` 检查覆盖情况；`unmatched_trade_ids` 给出仍待核对的交易。

关联必须是同一个 USD 券商账户；买入净结算款为 `-(股数 × 价格 + 手续费)`，卖出为 `股数 × 价格 − 手续费`。按净额正负选择转入或转出，允许不超过半美分的金额舍入差。净额恰为零不要求虚构现金流水。一条现金流水只能关联一笔成交，不能使用转账、换汇、冲销或已被冲销的记录；合并交割款需先根据真实成交明细拆分记录。

结算日期可以晚于成交日期。历史估值从成交日起纳入证券，同时计入待付买入款或待收卖出款；实际现金结算日取消对应待结算款，避免 T+1 产生虚假资产跳变。尚未交割的新交易无需编造未来流水，等实际交割后再关联；相关区间在此之前暂不展示连续净值和收益率。

关联后的交易不能直接修改、删除、撤销，对应现金也不能直接冲销。更正时先用 `cash_entry_id=null` 解除关联，再核对、更正来源记录并重新关联。关联操作也需要写权限、版本检查、幂等键和审计；Web/手机只读。

## 资产走势的计算

入口是“资产 → 资产走势”，独立详情中可选择金额、资金流调整净值或回撤，以及一个月、三个月、一年、全部区间。金额最多回看 30 年；窗口之前的交易和现金仍用于计算期初持仓与余额。已归档账户也保留在历史中。

```text
历史净资产 = 证券收盘市值 + 各账户现金 + 已关联待结算净款
区间损益 = 期末净资产 − 期初净资产 − 区间净外部流入
```

证券使用美东已完成交易日的同日未复权收盘价；非交易日记录归入下一个收盘估值。工资、期初资金和对外提款属于外部现金流；内部转账、证券结算不属于外部流，分红、利息和费用属于收益变化。跨币种转账按两边实际金额及当日参考汇率重估，成交汇率差异会影响资产表现。

金额和资金流都按选定的 USD、CNY、HKD 或 EUR 计算。估值用估值日的历史汇率，外部流用记账日期的历史汇率；只采用当时已经发布的参考价，最多沿用 7 个自然日。切换币种会重新计算整段收益率和回撤，而不是用当前汇率换一个货币符号。

## 净值和回撤

每个所选区间的首个收盘估值作为基准，净值归一为 1；首点已经包含的资金不重复计入区间外部流。由于记录只有日期，采用一致的日频假设：区间内入金视为期初，出金视为期末。

```text
单段增长倍数 = (本次收盘资产 + 本段外部出金) / (上次收盘资产 + 本段外部入金)
净值 = 上次净值 × 单段增长倍数
区间 TWR = 期末净值 − 1
回撤 = 当前净值 / 区间此前最高净值 − 1
最大回撤 = 区间内最小回撤
```

例如已有 1,000 元，工资再转入 1,000 元，资产变为 2,000 元且没有收益变化，净值仍为 1。提现也不会被当作亏损。外部资金流调整和分段几何链接的方法参考 [GIPS 官方资产所有者手册](https://www.gipsstandards.org/standards/gips-standards-for-asset-owners/gips-standards-handbook-for-asset-owners/)，本项目明确使用日频近似，不宣称盘中精确 TWR 或 GIPS 合规。

## 数据完整性

- 行情或历史汇率缺失时，金额曲线保持断点；净值不会跨缺口拼接，整段收益率及最大回撤不冒充完整结果。
- 结算关联缺失或无效时，首页与历史页都改称“已记录资产估值”，但未知应收应付款尚未计入，不能视为完整净资产；配置比例、目标差额、净值和收益指标暂不计算。行情或汇率也缺失时，连完整的记录估值也不显示。
- 零资产、单个估值点或没有可用投入资本时，不伪造收益率。计算范围、缺失标的、币种和交易编号由接口返回。
- 分红采用实际净到账口径，没有除息日至到账日的应收分红模型；期间的价格下调可能体现在回撤中。未复权日线也可能受拆股影响。
- 未记录的现金、资产或负债无法被计算。借贷、非 USD 证券及公司行动目前不建模；参考汇率不是银行的实际结算报价。

`GET /api/assets/history?period=1y&currency=CNY` 提供历史金额、净值、回撤、来源和完整性。`GET /api/settlements` 与 MCP `list_trade_settlements` 读取关联。业务 JSON 导出增加 `trade_settlements`；现有 v2 库在首次使用时创建空关联表，不自动匹配或改写任何历史资金记录。
