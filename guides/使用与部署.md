# 使用与部署指南

[返回首页](../README.md)

Accufolio 是 Agent 驱动的资产配置看板：你向自己的 Agent 提供资产操作、余额与目标，Agent 通过本地 MCP 维护数据，Web 和手机负责只读展示组合、趋势与配置差额。应用不内置 AI 模型；部署完成后，还需按下文连接 MCP，才能让 Agent 更新投资账户。

## 快速开始

需要 Python 3.11–3.13。建议使用独立虚拟环境。

```bash
git clone https://github.com/zuquanzhi/Accufolio.git
cd Accufolio
python -m venv .venv
source .venv/bin/activate  # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
export ACCUFOLIO_PASSWORD='设置你自己的长密码'
# PowerShell: $env:ACCUFOLIO_PASSWORD='设置你自己的长密码'
uvicorn apps.api.main:app --host 127.0.0.1 --port 8000
```

访问 `http://127.0.0.1:8000`。浏览器弹出的登录框中，默认用户名是 `admin`，密码是上面设置的值。没有默认密码。应用使用 HTTP Basic 认证，远程访问必须使用 HTTPS。仅运行一个 Uvicorn worker，避免重复启动后台任务。

| 环境变量 | 默认值 | 用途 |
|---|---|---|
| `ACCUFOLIO_PASSWORD` | 必填 | 浏览器/API 密码 |
| `ACCUFOLIO_USER` | `admin` | 登录用户名 |
| `ACCUFOLIO_DB` | `data/accufolio.db` | 数据库位置 |
| `ACCUFOLIO_SCAN_INTERVAL` | `300` | 扫描间隔秒数，最少 60 |
| `ACCUFOLIO_MCP_SCOPE` | `read` | MCP 本地进程权限，可设为 `write` |
| `ACCUFOLIO_WEBHOOK_URL` | 空，关闭 | HTTPS 通知接收地址，不在界面中暴露 |
| `ACCUFOLIO_WEBHOOK_TOKEN` | 空 | 可选的 Bearer 令牌 |

依赖版本固定在 `requirements.txt`。数据库会自动创建；首次启动会初始化表结构，不会导入历史种子数据。

## Docker 与 HTTPS

```bash
cp .env.example .env
# 编辑 .env 设置密码
docker compose up -d --build
```

容器以非 root 用户运行，端口默认只绑定 `127.0.0.1:8000`；数据库保存在 `accufolio_data` 卷。若你已有 HTTPS 反向代理，将它指向此端口即可。

也可在 `.env` 设置 `ACCUFOLIO_DOMAIN=你的域名`，将域名 DNS 指向服务器并开放 80/443，再启动 Caddy 自动申请证书：

```bash
docker compose -f compose.yml -f compose.https.yml up -d --build
```

## Android APK 下载与安装

在 [最新 Release](https://github.com/zuquanzhi/Accufolio/releases/latest) 的 **Assets** 中下载以 `.apk` 结尾的安装包，不要下载源码 ZIP。支持 Android 10 及以上。按系统提示允许当前下载来源安装应用，安装后输入你部署的 Accufolio **HTTPS 根地址**并登录。

APK 是连接自托管服务器的 Android 客户端，**不内置服务器或示例账户**，需要先按上文部署后端。只允许连接指定的 HTTPS 站点，不允许明文 HTTP 或无效证书。用户名、密码仅用于当前会话，不由客户端写入磁盘。交易导出文件保存在手机「下载」目录。

服务器发布新的网页功能后，客户端会自动检测更新并保护未保存的表单；无需重新下载安装。从 v1.2.0 起可在应用内检查、下载并验证原生更新，然后由 Android 系统请求安装确认；从 v1.1.0 升级需先安装一次新版 APK。正式 APK 使用同一个发布密钥签名，后续版本支持覆盖安装。

构建环境：JDK 17、Gradle 8.11.1、Android SDK 35。`gradle -p apps/mobile testDebugUnitTest lintDebug assembleDebug` 可构建测试包。正式发布使用 GitHub Secrets 中的 `ANDROID_KEYSTORE_BASE64` 和 `ANDROID_KEYSTORE_PASSWORD`，私钥不进入源码或 Release。

## PWA 安装和升级

用 Android Chrome 或 iOS Safari 打开你的 **HTTPS** 站点，选择「安装应用」/「添加到主屏幕」。这是联网使用的 PWA，**不是原生 APK**。服务器部署新版本后，手机会检测并加载新网页，无需重新下载安装包。首次安装入口取决于系统和浏览器；已完成浏览器回归；实体手机兼容性仍需实际设备验证。

服务端升级仍由部署者操作：先备份，再 `git pull --ff-only`，然后 `docker compose up -d --build`。Python 运行方式需重新安装依赖并重启服务。不要使用 `docker compose down -v`，它会删除数据卷。

## 备份与恢复

后台每天启动一次 SQLite 在线备份，保存到数据库旁的 `backups/`；系统面板也可手动创建备份。自动备份与原库在同一磁盘，建议将备份复制到独立存储。当前不自动清理旧备份，请监测磁盘空间。

恢复时先停止应用，将选定备份复制为配置的数据库文件，保留原文件副本，再启动应用。JSON 导出用于查看与迁移交易，不包含审计和监控数据；完整恢复请使用 `.db` 备份。

## 看板与资产配置

应用负责展示和分析资产。买卖记录、其他资金与配置目标通过具有写权限的本地 MCP 客户端维护，不在手机界面手动修改。持仓成本采用移动加权平均法，按交易日期顺序检查超卖；旧版未标明方向的交易作为买入保留。MCP 工具的 `side` 使用 `buy` 或 `sell`，未指定时默认 `buy`。

### 当前持仓与收益

首页汇总所有当前持有标的，显示市值、剩余成本、浮动盈亏、已实现盈亏和净投入。基础口径为：

| 指标 | 计算方法 |
|---|---|
| 持仓市值 | 各标的当前股数 × 当前价格，汇总所有持仓 |
| 持仓成本 | 买入增加成本；卖出按当时移动平均成本扣减 |
| 浮动盈亏 | 持仓市值 − 剩余持仓成本 |
| 已实现盈亏 | 累计卖出所得 − 对应卖出股数的移动平均成本 |
| 累计净投入 | 累计买入金额 − 累计卖出金额 |
| 累计盈亏 | 持仓市值 − 累计净投入，等于已实现与浮动盈亏之和 |

净投入可能在卖出后变为负数，并不代表负持仓。任一当前持仓缺少行情时，整体市值与依赖它的指标显示不可计算，不把部分已知行情当作完整估值。成本与股数仍可根据交易记录展示。未来日期的交易尚未计入当前看板。

XIRR 为按实际天数 / 365 计算的资金加权年化收益率，纳入买入、卖出与期末持仓价值；同日现金流先合并。已全部卖出的组合以最后一笔有效现金流结束，不人为添加今天的零余额。少于 90 天的样本不计算年化；支持的利率区间为 −99.99% 至 1000%。出现多个解、没有可用解或不能可靠确认唯一解时显示原因，不任意选择一个数字。切换曲线区间不会把这项整体现金流指标改成区间年化。

### 投资组合与全部资产

「投资组合」仅包含股票持仓，可选择市值、剩余成本或股数作为分母查看占比。股数占比只表示持有数量，不能代表资金权重或风险敞口。

「全部资产」以**当前股票市值 + 其他资金余额**计算。其他资金由 AI 根据你提供的信息独立填报，以 USD 计价，同时保存余额的截至日期。工资、支出或转账发生后需要显式更新；买入、卖出不会自动改变它，系统也不会用买卖差额猜测现金余额。未填报与明确填报为零是不同状态；缺少余额或行情时，不将未知项默认为零组成一个完整总额。

两个视角分别维护目标比例，均以市值口径比较。目标金额为所选视角总额 × 目标比例；目标金额减当前金额为差额，正数表示距目标仍有缺口，负数表示超过目标。成本和股数视图不计算目标调配金额。目标是观察配置的参照，不执行券商交易或生成自动下单任务。

### 历史曲线

可查看近一个月、三个月、一年或全部记录，全部区间最多展示最近 30 年。持仓市值由已记录的买卖和新浪**未复权收盘价**重建；买卖在记录日期计入持仓，非交易日仅沿用此前已知收盘价，最多延用 7 天。没有可用价格的日期保留缺口，绝不使用未来价格补齐。窗口之前的交易仍计入期初股数与净投入。

曲线中的净投入为累计买入减累计卖出，累计盈亏为当日持仓市值减净投入。投入增加会抬升市值曲线，不能直接把资产增长当作投资收益率。曲线不含完整账户现金、分红和手续费，**不是账户净值或时间加权收益曲线**；当前填报的其他资金不会倒填到过去日期。拆股与其他公司行动也可能影响未复权价格及重建结果，来源、过期和缺失状态会在界面中提示。

图表支持触摸、鼠标和键盘左右键读取日期与数值，点击图例可显示或隐藏曲线。持仓汇总与历史数据分开加载，读取日线期间仍可切换页面。

## 旧版设备记录

v1.5.0 保留此前「随手记」的浏览器存储数据，提供只读查看和 JSON 导出，不再提供手动增删改。旧数据仍留在当前设备、当前站点的浏览器或 WebView 中，不上传、不自动合并到投资账户，也不包含在服务器数据库备份里。清除站点数据或卸载应用前请先导出。界面仍需连接服务器加载，不能作为独立离线应用启动。

## MCP 接入

MCP 服务为本地 stdio 进程，需要在能直接访问服务器所用 SQLite 数据库的机器上运行，且 `ACCUFOLIO_DB` 必须指向同一个数据库；如果服务运行在 Docker 命名卷中，需要配置共享的数据库路径并赋予相应权限。仅在另一台电脑启动 MCP 不会自动连接远程服务器；当前不提供远程 MCP。

桌面客户端启动 `scripts/mcp_server.py`。路径需使用你机器上的绝对路径，例如 Windows：

```json
{
  "mcpServers": {
    "accufolio": {
      "command": "D:/program/Accufolio/.venv/Scripts/python.exe",
      "args": ["D:/program/Accufolio/scripts/mcp_server.py"],
      "env": {
        "ACCUFOLIO_DB": "D:/program/Accufolio/data/accufolio.db",
        "ACCUFOLIO_MCP_SCOPE": "read"
      }
    }
  }
}
```

本地进程以启动用户的系统权限访问数据库。改为 `write` 才能写入。交易写工具默认 `dry_run=true`，提交需设置为 `false`；每次新操作用一个唯一 `idempotency_key`，重试同一操作保留该键。相同键搭配不同数据会拒绝。不要将本地 stdio 服务直接代理到公网；当前不提供远程 MCP。

### 看板与配置工具

| MCP 工具 | 用途 |
|---|---|
| `get_dashboard(period="1y")` | 读取多标的汇总、持仓占比与重建曲线；`period` 可为 `1m`、`3m`、`1y`、`all`。 |
| `get_allocation_plan()` | 读取其他资金、两个视角的配置目标、备注、更新时间和 `revision`。 |
| `set_allocation_plan(...)` | 预览或替换配置，要求 `write` 权限、最新版本号与唯一幂等键。 |

配置更新的完整参数为 `expected_revision`、`idempotency_key`、`reserve_amount`、`reserve_as_of`、`investment_targets`、`total_targets`、`note`、`dry_run`。其中：

- `reserve_amount` 为非负的 USD 其他资金余额，填写金额时必须同时填写 `reserve_as_of`；日期不得晚于今天。两个字段同时为 `null` 表示未填报。
- 两份 `targets` 的数值使用百分数，例如 `60` 表示 60%，非空目标必须合计 100。`investment_targets` 只含股票标的；`total_targets` 使用保留键 `__RESERVE__` 表示其他资金，股票代码 `CASH` 仍指该股票本身。空字典表示清除该视角的目标。
- 这是**全量替换**，不是局部更新。更新其中一项时也要带上希望保留的余额、日期、另一份目标和备注；省略可选项会恢复其空值。
- 先读 `get_allocation_plan()` 得到 `revision`，将它作为 `expected_revision`。其他写入已改变配置时会拒绝覆盖，需重新读取。成功写入增加版本并保存审计；配置变更不支持交易撤销工具，应读取最新版后再提交替换。

例如首次配置、读取到 `revision=0` 时，可用以下参数预览（日期与金额仅为示例）：

```json
{
  "expected_revision": 0,
  "idempotency_key": "allocation-plan-example-001",
  "reserve_amount": 5000,
  "reserve_as_of": "2026-11-14",
  "investment_targets": {"QQQM": 60, "SPY": 40},
  "total_targets": {"QQQM": 45, "SPY": 30, "__RESERVE__": 25},
  "note": "根据最新余额与长期配置目标更新",
  "dry_run": true
}
```

确认预览后使用同样参数、设置 `dry_run=false` 提交。网络重试同一提交时保持幂等键、原版本号和完整内容一致；下一次新更新重新读取版本并使用新键。HTTP 界面只读取 `GET /api/dashboard` 与 `GET /api/allocation`，配置没有 HTTP 写入入口。

## 回测口径

在「发现」选择美股标的和日期即可获取新浪日线并回测。日线按标的存入 SQLite，缓存有效期 6 小时；获取失败后冷却 5 分钟再重试，有旧缓存时显式标为过期，无数据则提示失败。每次请求最长 30 年，数据覆盖取决于提供方。自动数据为**未复权收盘价**，不包含分红再投资，拆股区间可能使结果失真；页面会显示来源、缓存状态与口径。

「手动数据」仍支持每行 `YYYY-MM-DD,收盘价`；日期必须严格递增。每月第一条数据代表该月投入时点。支持碎股，忽略手续费、税费、现金利息和分红；手动输入是否复权由提供者负责。

固定月投花完当月现金；季度投入在 1/4/7/10 月首条数据买入；等待回撤在近 20 条价格回撤达到 5% 时投入一半现金，冷却 5 条数据；定投加码每月先投 2/3，达到 5%/8.75% 回撤时从现金池加码。所有策略期末资产包含未投入现金。最大回撤是**标的收盘价**回撤，不是受入金影响的账户资产回撤。历史结果不代表未来收益。

结果优先展示四种策略的资产曲线和累计投入虚线，可按日期比较，也可点击图例单独查看策略。「比较期末结果」中展开投入、资产、收益与年化表格。该曲线来自假设的定投规则，与首页基于真实交易记录重建的持仓曲线分开；不会写入你的账本。

## 监控规则

设涨跌幅阈值为 2%，绝对涨跌幅达到 2% / 4% / 6% 时分别为 L1 / L2 / L3。同一 UTC 日期、同一标的与方向，只在首次触发或级别升级时告警；上涨与下跌分别记录，重复扫描不会重复发送同一级别。

退潮信号使用新浪标的日线和 [Cboe 官方 VIX 历史收盘价](https://www.cboe.com/tradable-products/vix/vix-historical-data/)，取最近 20 个共同交易日：标的较窗口高点回撤至少 8%，且 VIX 较同期高点回落至少 25% 时触发。按共同交易日去重。数据缺失、过期或无法对齐时跳过并展示原因；这是一条固定的观察规则，不是交易指令。

## Webhook 告警

在部署环境的 `.env` 中设置 `ACCUFOLIO_WEBHOOK_URL=https://你的接收服务/路径`，可选设置 `ACCUFOLIO_WEBHOOK_TOKEN`，然后重启服务（Compose 运行方式重新执行 `docker compose up -d`）。Python 直接运行不会自动读取 `.env`，需设置对应进程环境变量。接收端必须支持通用 JSON POST；聊天机器人若要求专有格式，需要转换服务。

新产生的涨跌分级、退潮和行情源异常告警会与投递任务一起写入数据库。未配置地址时完全关闭外发，不回补历史告警。请求仅允许 HTTPS、禁止重定向、超时 10 秒；配置的令牌作为 `Authorization: Bearer …` 发送。响应为 2xx 视为接收成功，不代表下游手机已经收到通知。

```json
{
  "schema": "accufolio.alert.v1",
  "event_id": "稳定的事件 UUID",
  "created_at": "2026-11-14T00:00:00+00:00",
  "alert": {
    "id": 42,
    "symbol": "QQQM",
    "kind": "move",
    "level": 2,
    "message": "L2 · QQQM 涨跌幅 -4.20%，达到 4% 阈值",
    "as_of": "2026-11-14"
  }
}
```

`kind` 为 `move`、`calm` 或 `source`；非涨跌告警的 `level` 为 `null`。请求头的 `Idempotency-Key` 与 `event_id` 相同。投递为至少一次语义：连接中断或进程退出后可能重复，接收端应按 `event_id` 去重。最多尝试 8 次，退避从 60 秒增加到 1 小时，由后台扫描周期检查到期任务，因此实际间隔也受 `ACCUFOLIO_SCAN_INTERVAL` 影响。

「发现」显示通知状态；修复配置后可重试已失败任务。认证接口 `GET /api/notifications/status` 返回待投递、投递中、成功与失败数量；`POST /api/notifications/retry` 需 `X-Accufolio: 1`。地址与令牌不写入投递记录或状态响应，待投递消息使用重试时的当前配置。

Actions 验证 Python 3.11/3.12/3.13、Chromium 浏览器流程、Docker 启动、Android 单元测试与 lint，并在 Android 15 模拟器验证欢迎页、HTTPS 连接、认证、四页切换和原生设置入口。浏览器测试覆盖无刷新导航、离线切换已加载页面、慢请求隔离、草稿恢复和自动回测。图表回归覆盖触摸与键盘、空值断点、单点、负值、缩放和页面重新挂载；可访问性语义由浏览器验证，实体屏幕阅读器仍需实际设备测试。通知测试使用模拟接收端，不向真实地址发送。推送 `v*` 标签时会重新运行完整验证，成功后创建 Release，附签名 APK、源码 ZIP 和 SHA-256 校验文件。

## 范围

当前版本专注单用户、USD 投资看板，不执行交易下单。暂不支持分红、手续费、多币种、券商同步、原生 APNs/FCM 推送和远程 MCP；外部通知使用可选 Webhook。其他资金是独立报告的余额快照，不是可从交易自动结算的现金账本。实时行情来自第三方，可能延迟、受限或不可用。历史参考材料留在本地，未纳入发布。[路线图](roadmap.md) 记录后续缺口与明确不做的范围。

`apps/api`：FastAPI；`apps/web`：响应式 Web/PWA；`packages/core`：纯计算；`packages/providers`：行情；`packages/mcp`：MCP；`tests`：单元与接口测试；`scripts/browser_smoke.py`：浏览器回归。

## 页面与客户端升级

从 v1.4.0 起使用四个独立路径：`/assets`、`/records`、`/discover`、`/settings`。应用内通过客户端路由切换并保留页面，不会每次重新加载整个文档。直接打开或刷新路径时由服务端返回对应页面。部署 v1.5.0 时需同步更新服务端；仅安装新 APK 不会升级自托管站点。Android 的连接地址、检查更新与重新载入由设置页直接操作，正常页面不附加原生设置底栏。旧的 `/#assets` 等书签会转到相应页面。

切换页面会保留分析参数与当前会话中的草稿；这是临时会话数据，不是备份。v1.5.0 不提供交易编辑表单；此前保存的随手记继续使用原有设备存储，只读展示与导出，不自动迁移到投资账户。
