# 使用与部署指南

[返回首页](../README.md)

Accufolio 是 Agent 驱动的资产配置看板：Agent 通过本地 MCP 维护账户、现金流水、证券交易和目标权重，Web 与手机提供只读资产总览和投资分析。应用不内置 AI 模型；部署完成后，还需按下文连接 MCP，才能让 Agent 更新投资账户。

## 快速开始

需要 Python 3.11–3.13。建议使用独立虚拟环境。

```bash
git clone https://github.com/zuquanzhi/Accufolio.git
cd Accufolio
python -m venv .venv
source .venv/bin/activate  # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
export ACCUFOLIO_PASSWORD='设置你自己的长密码'
# PowerShell: $env:ACCUFOLIO_PASSWORD='设置你自己的长密码'
uvicorn apps.api.main:app --host 127.0.0.1 --port 8000
```

访问 `http://127.0.0.1:8000`。在登录页输入默认用户名 `admin` 和上面设置的密码；没有默认密码。可选择保持登录，远程访问必须使用 HTTPS。仅运行一个 Uvicorn worker，避免重复启动后台任务与分散登录限速计数。

| 环境变量 | 默认值 | 用途 |
|---|---|---|
| `ACCUFOLIO_PASSWORD` | 必填 | 浏览器/API 密码 |
| `ACCUFOLIO_USER` | `admin` | 登录用户名 |
| `ACCUFOLIO_DB` | `data/accufolio.db` | 数据库位置 |
| `ACCUFOLIO_PUBLIC_ORIGIN` | 空 | HTTPS 反向代理的公开源地址，如 `https://invest.example.com`，不含路径 |
| `ACCUFOLIO_LOGIN_MAX_ATTEMPTS` | `10` | 同一连接来源允许的登录失败次数 |
| `ACCUFOLIO_LOGIN_COOLDOWN` | `300` | 登录失败计数窗口及达到上限后的冷却秒数 |
| `ACCUFOLIO_MAINTENANCE_INTERVAL` | `300` | 自动备份检查及失败重试间隔秒数，最少 60 |
| `ACCUFOLIO_BACKUP_KEEP` | `30` | 保留的有效自动日备份份数，至少 1 |
| `ACCUFOLIO_MCP_SCOPE` | `read` | MCP 本地进程权限，可设为 `write` |

依赖版本固定在 `requirements.txt`。数据库会自动创建；首次启动会初始化表结构，不会导入历史种子数据。

## Docker 与 HTTPS

```bash
cp .env.example .env
# 编辑 .env 设置密码
docker compose up -d --build
```

容器以非 root 用户运行，端口默认只绑定 `127.0.0.1:8000`；数据库保存在 `accufolio_data` 卷。若你已有 HTTPS 反向代理，将它指向此端口，并设置 `ACCUFOLIO_PUBLIC_ORIGIN=https://你的域名`。这使内部 HTTP 连接也能正确校验浏览器的公开 Origin，并签发 Secure Cookie；不通过任意 `X-Forwarded-*` 请求头决定信任关系。

也可在 `.env` 设置 `ACCUFOLIO_DOMAIN=你的域名`，将域名 DNS 指向服务器并开放 80/443，再启动 Caddy 自动申请证书：

```bash
docker compose -f compose.yml -f compose.https.yml up -d --build
```

附带的 `compose.https.yml` 根据 `ACCUFOLIO_DOMAIN` 自动配置公开源地址。公开源只接受 HTTPS、域名和可选端口，不接受用户名、密码、路径或查询参数。更新部署环境后需重新创建容器；Python 直接运行需设置进程环境变量。

## 登录与设备会话

登录页的「在此设备保持登录」默认开启，会话最长有效 90 天，期限不会因查看页面而自动延长。取消勾选则使用浏览器会话 Cookie，服务端最多保留 24 小时。设备保存不透明令牌，SQLite 只保存其摘要；密码不会写入应用存储。Cookie 为 HttpOnly、SameSite=Strict，HTTPS 下使用 Secure。Android 会持久化 Cookie，因此关闭或重新打开应用无需重复输入密码。

设置中的「退出登录」会撤销当前设备会话；更换站点用户名或密码会使现有会话失效。API 客户端仍可使用 HTTP Basic。`POST /api/session` 接收 `username`、`password`、`remember`；`GET /api/session` 读取当前会话，`DELETE /api/session` 退出。登录和退出均需 `X-Accufolio: 1`，浏览器请求还校验 Origin。

表单登录和 Basic 密码验证共用失败限速：默认同一连接来源在 300 秒内失败 10 次后，冷却 300 秒并返回 `429` 与 `Retry-After`；成功验证重置计数。限速为进程内有界状态，重启会重置，不是永久账户锁定。来源取 ASGI 连接地址，不自行信任任意转发 IP 请求头；反向代理可能让多个设备共用同一计数，符合当前单用户部署方式。

## Android APK 下载与安装

在 [最新 Release](https://github.com/zuquanzhi/Accufolio/releases/latest) 的 **Assets** 中下载以 `.apk` 结尾的安装包，不要下载源码 ZIP。支持 Android 10 及以上。按系统提示允许当前下载来源安装应用，安装后输入你部署的 Accufolio **HTTPS 根地址**并登录。

APK 是连接自托管服务器的 Android 客户端，**不内置服务器或示例账户**，需要先按上文部署后端。只允许连接指定的 HTTPS 站点，不允许明文 HTTP 或无效证书。密码不写入磁盘；保持登录使用上述可撤销会话。交易导出携带当前会话，文件保存在手机「下载」目录。

服务器发布新的网页功能后，客户端会自动检测更新并保护未保存的表单；无需重新下载安装。从 v1.2.0 起可在应用内检查、下载并验证原生更新，然后由 Android 系统请求安装确认；从 v1.1.0 升级需先安装一次新版 APK。正式 APK 使用同一个发布密钥签名，后续版本支持覆盖安装。

构建环境：JDK 17、Gradle 8.11.1、Android SDK 35。`gradle -p apps/mobile testDebugUnitTest lintDebug assembleDebug` 可构建测试包。正式发布使用 GitHub Secrets 中的 `ANDROID_KEYSTORE_BASE64` 和 `ANDROID_KEYSTORE_PASSWORD`，私钥不进入源码或 Release。

## PWA 安装和升级

用 Android Chrome 或 iOS Safari 打开你的 **HTTPS** 站点，选择「安装应用」/「添加到主屏幕」。这是联网使用的 PWA，**不是原生 APK**。服务器部署新版本后，手机会检测并加载新网页，无需重新下载安装包。首次安装入口取决于系统和浏览器；已完成浏览器回归；实体手机兼容性仍需实际设备验证。

服务端升级仍由部署者操作：先备份，再 `git pull --ff-only`，然后 `docker compose up -d --build`。Python 运行方式需重新安装依赖并重启服务。不要使用 `docker compose down -v`，它会删除数据卷。

## 备份、导出与恢复

后台每个 UTC 日期创建一次 SQLite 在线备份，保存到数据库旁的 `backups/`；先生成临时文件并验证完整性，再原子替换当天副本。自动备份只轮转名称为 `accufolio-YYYY-MM-DD.db` 且校验通过的文件，默认保留最近 30 份，不清理手动备份、其他文件或损坏的副本。设置中也可手动备份；失败会在设置中显示，并在下一轮维护时重试。备份与原库在同一磁盘，建议另存到独立存储。

恢复时先停止应用，将选定备份复制为配置的数据库文件，保留原文件副本，再启动应用。`GET /api/export` 导出 `accufolio-v2` JSON，包含账户、现金流水、交易、汇率快照、共享设置与配置目标，不包含登录会话或密钥。它用于检查和外部处理；应用不提供旧版导入或恢复按钮。完整恢复使用兼容当前表结构的 `.db` 备份。

## 资产与投资

`/assets` 是默认首页，展示证券市值、现金账户余额及净资产合计，按账户核对金额、币种、用途与流水。流水显示逐笔原币余额、冲销关联和转账对手账户；账户刷新失败会明确清除无法确认的估值。`/investments` 单独展示证券表现；配置和收益详情分别位于 `/investments?detail=allocation` 与 `/investments?detail=performance`。证券市值、现金余额和收益率各有口径，不通过切换两套账本混在一起。

记录页支持按标的、账户名或备注搜索，并组合筛选账户、买卖方向和月份。每次先展示 50 条，可继续展开；页面切换保留筛选条件。记录页为证券买卖，现金流水在对应账户详情查看。

账户流水请求使用 `GET /api/accounts/{id}/cash-entries?expected_revision=N` 与汇总版本对齐；版本已变化时返回 409，页面明确提示重新同步，不混用旧流水与新余额。省略版本参数仍可读取最新完整流水。

一个账户只有一个记账币种。现金余额为该账户有效流水的 `SUM(amount)`，证券按 `(account_id, symbol)` 单独核算持仓成本，最后汇总。净资产为证券市值与现金余额折算后的总和；当前不支持负债或负现金余额。完整字段、约束与公式见[数据模型](schema-v2.md)。

### 行情与历史曲线

顶部证券估值使用最新可用行情，显示提供方真实时间。新浪失败后尝试腾讯；全部失败时估值保持未知，不以历史收盘价替代实时价格。每一笔证券交易明确归属 USD 券商账户，包含手续费和策略标签；当前不支持非 USD 证券。

历史曲线使用美东已完成交易日的同日未复权收盘价；[exchange_calendars](https://github.com/gerrymanoim/exchange_calendars) 的 `XNYS` 日历处理周末、假日、夏令时和提前收盘，交易时段参考 [NYSE 官方日历](https://www.nyse.com/trade/hours-calendars)。缺失价格留空，末点停在最后完整估值，不用旧价格向前补成今天。非交易日不新增点，当日记录的交易计入下一个交易日的持仓。

近一个月、三个月、一年或全部记录可切换；全部区间最多 30 年。窗口之前的交易仍决定期初持仓。该曲线不含全部现金账户或负债，不是完整账户净值。未实现与已实现收益分别显示；XIRR 使用美元证券买卖、手续费及可归属的已到账净分红；现金利息只进入全账户分析。另有“资产 → 资产走势”展示完整账户范围的金额、资金流调整净值及回撤，详见[收益说明](performance.md)。

### 币种与时间偏好

共享设置位于 `settings` 表，默认 `display_currency=USD`、`market_timezone=America/New_York`。设备可在设置中覆盖展示偏好，不改写资产记录；未覆盖时读取 `GET /api/settings` 的共享默认值。美股交易日和收盘判断始终使用美东交易所日历，不随设备展示时区改变。

展示支持 USD、CNY、HKD、EUR。当前金额使用 [ECB 参考汇率](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html) 的最新快照；历史金额按各日期使用当日或此前已发布的汇率，最多沿用 7 个自然日，找不到即留空。1999 年以前或某币种开始发布之前的缺口不会用后来的数据填充。每个折算点保留汇率日期、来源和抓取时间；这不是银行实际结算价。

`GET /api/fx` 提供最新参考价；`GET /api/fx/history?start=YYYY-MM-DD&end=YYYY-MM-DD&base=USD` 提供逐日 `rates`、`rate_dates`、`sources` 与 `fetched_ats`。缓存有效 6 小时，失败后冷却 5 分钟，读取旧缓存时明确标记；无汇率时不会将原币金额直接换个符号。历史曲线中的美元指标按当日汇率展示等值；XIRR 保持美元口径，不宣称是外币资金加权收益率。

## MCP 接入

MCP 是本地 stdio 进程，必须能直接访问 Web 服务使用的同一 SQLite 文件。Docker 命名卷需要配置可共享的路径与权限；在另一台机器启动 MCP 不会自动连接远程服务器。当前不提供远程 MCP。

例如 Windows 客户端配置：

```json
{
  "mcpServers": {
    "accufolio": {
      "command": "D:/program/Accufolio/.venv/Scripts/python.exe",
      "args": ["D:/program/Accufolio/scripts/mcp_server.py"],
      "env": {
        "ACCUFOLIO_DB": "D:/program/Accufolio/data/accufolio.db",
        "ACCUFOLIO_MCP_SCOPE": "read"
      }
    }
  }
}
```

先用只读工具核对连接。写入需将本地进程 `ACCUFOLIO_MCP_SCOPE` 改为 `write`。账户、现金、交易、目标和共享设置工具默认 `dry_run=true`；提交使用 `false`。每次新操作使用新的非空 `idempotency_key`，重试保持原键与完整参数；相同键配不同内容会拒绝。交易撤销工具不是预览接口，请按工具说明调用。

| 工具 | 用途与关键参数 |
|---|---|
| `get_assets()` | 读取净资产、账户原币余额、证券市值、折算日期和完整性。 |
| `list_accounts()` / `list_cash_entries(account_id)` | 核对账户、现金明细及最新账户 `revision`。 |
| `set_account(...)` | 新建或全量替换元数据，包含名称、类型、用途、币种、机构、日期、归档状态和备注；新账户 `expected_revision=0`。 |
| `add_cash_entry(...)` | 追加账户原币现金流水；需账户 ID、日期、类型、有符号金额、币种和最新版本。 |
| `transfer_cash(...)` | 同时记录转出、转入；需两边账户 ID、实际金额、各自版本和日期。跨币种按实际两边金额记录换汇比例。 |
| `reverse_cash_entry(...)` | 用关联的反向流水更正未成对的单笔记录，保留原记录；不直接擦除历史。 |
| `list_trades()` / `add_trade` / `update_trade` / `delete_trade` | 读取或维护证券记录，明确账户、USD 币种、股数、价格、手续费与策略；按账户检查超卖。 |
| `get_asset_history(period="1y", currency="USD")` | 所有账户的历史估值、日频近似 TWR、净值与回撤，附缺口和未关联交易编号。 |
| `list_trade_settlements()` / `set_trade_settlement(...)` | 读取或预览关联真实成交与现金流水；写入需账户版本、幂等键与 `dry_run=false`，传空流水 ID 解除关联。 |
| `get_cost_basis_calibrations()` / `set_cost_basis_calibration(...)` | 核对账户、标的与对账单日期，用券商累计已实现盈亏校准持仓的盈亏拆分。预览和提交使用账户版本与幂等键。详见[成本计算说明](performance.md#持仓成本与券商对账)。 |
| `get_dashboard(period="1y")` | 全部证券的汇总与历史曲线，区间支持 `1m`、`3m`、`1y`、`all`。 |
| `get_summary(symbol)` | **单标的**统计，`symbol` 必填，响应 `scope="single_symbol"`。不是账户或净资产汇总。 |
| `get_allocation_targets()` / `set_allocation_targets(...)` | 读取或替换一个范围的目标权重，需 `expected_revision`；另一范围不变。 |
| `get_settings()` / `set_settings(...)` | 读取或全量替换共享默认币种与时区，需最新版本和幂等键。 |
| `get_health()` | 读取数据库、自动备份和后台运行状态。 |

### 账户与现金

账户 `kind` 使用 `broker`、`bank`、`ewallet`、`provident`、`other`；`purpose` 使用 `investing`、`savings`、`emergency`、`spending`、`housing_fund`。类型说明机构形态，用途说明资金职责。已有现金或证券记录的账户不能随意改变币种，归档前需要结清余额与持仓。

`add_cash_entry` 的正向类型为 `balance_open`、`deposit`、`interest`、`dividend`；`withdraw`、`fee` 使用负金额。期初余额必须是第一笔现金记录。成对转账与换汇应使用 `transfer_cash`，不要将两条流水分开提交；一边失败会整笔回滚。单笔更正追加反向流水，不删除原条目；已成对的转账应通过相反方向的成对操作更正。

**证券交易不会自动增加或减少现金流水。** Agent 应根据实际结算分别记交易和资金变动，例如买入对应的真实现金支出、卖出实际收到的净额；不得从既有持仓推测或补造初始资金。已归属同券商账户与标的的 USD 净分红会进入证券总回报及 XIRR。证券结算需通过 `set_trade_settlement` 与实际现金流水关联，供资产净值正确剔除内部交割款。现金余额未对齐真实账户时，净资产也不会正确。

### 交易与目标

证券交易支持 `account_id`、`currency="USD"`、`fee`（非负，同币种）和 `strategy`。策略值为 `dca`、`dip_add`、`rebalance`、`manual`，是交易标签；与账户的资金用途分开。买入手续费计入成本，卖出手续费扣减收入，美元 XIRR 使用净现金流。

`set_allocation_targets(scope, targets, expected_revision, idempotency_key, dry_run=true)` 只存权重。`scope="securities"` 的键是股票代码；`scope="net_worth"` 的键为 `account:<id>`，指向有效账户。非空权重必须合计 100%，空字典清除此范围目标。更新一个范围时保留另一个；没有手填的「其他资金」金额或保留键。

HTTP `GET /api/summary?symbol=QQQM` 必须提供标的；全部证券使用 `/api/dashboard`，账户及净资产使用 `/api/assets`。账户、现金、目标和共享设置的 HTTP 接口只读，资产写入通过 MCP。

## 回测口径

在「发现」选择美股标的和日期即可获取新浪日线并回测。日线按标的存入 SQLite，缓存有效期 6 小时；获取失败后冷却 5 分钟再重试，有旧缓存时显式标为过期，无数据则提示失败。每次请求最长 30 年，数据覆盖取决于提供方。自动数据为**未复权收盘价**，不包含分红再投资，拆股区间可能使结果失真；页面会显示来源、缓存状态与口径。

「手动数据」仍支持每行 `YYYY-MM-DD,收盘价`；日期必须严格递增。每月第一条数据代表该月投入时点。支持碎股，忽略手续费、税费、现金利息和分红；手动输入是否复权由提供者负责。

固定月投花完当月现金；季度投入在 1/4/7/10 月首条数据买入；等待回撤在近 20 条价格回撤达到 5% 时投入一半现金，冷却 5 条数据；定投加码每月先投 2/3，达到 5%/8.75% 回撤时从现金池加码。所有策略期末资产包含未投入现金。最大回撤是**标的收盘价**回撤，不是受入金影响的账户资产回撤。历史结果不代表未来收益。

结果优先展示四种策略的资产曲线和累计投入虚线，可按日期比较，也可点击图例单独查看策略。「比较期末结果」中展开投入、资产、收益与年化表格。该曲线来自假设的定投规则，与首页基于真实交易记录重建的持仓曲线分开；不会写入你的账本。

## 自动备份与运行状态

后台只承担自动备份维护，行情和历史数据在查看页面或回测时按需获取。设置中的运行状态读取 `GET /api/health`，显示数据库检查、备份完成时间与 `worker` 心跳。后台失败或长时间没有心跳会明确显示，详细异常只写入服务日志，不把底层路径或凭据暴露到页面。

2.2 移除了行情关注、阈值扫描、提醒记录、Webhook 投递、退潮信号和扫描日报；相关 HTTP 与 MCP 工具已删除，旧通知环境变量不再使用。已有 v2 数据库中的旧监控表不会被自动删除，也不会继续读取或写入；账户、流水、交易与审计保留原样。新库不再创建这些表。

## 范围

当前版本为单用户、原币现金账户与 USD 美股交易看板。交易费用已计入证券成本和收益；已到账净分红计入证券收益，资产走势重建全账户金额、资金流调整净值与回撤。暂不支持非 USD 证券、负债、应收分红、公司行动、券商同步和远程 MCP。行情可能延迟、受限或不可用。[路线图](roadmap.md) 记录后续缺口与明确不做的范围。

`apps/api`：FastAPI；`apps/web`：响应式 Web/PWA；`packages/core`：纯计算；`packages/providers`：行情；`packages/mcp`：MCP；`tests`：单元与接口测试；`scripts/browser_smoke.py`：浏览器回归。

## 页面与版本升级

最终页面为 `/assets`、`/investments`、`/records`、`/discover`、`/settings`，资产为默认首页。应用内切换和详情返回保持同一文档，直接打开路径也可加载相应页面；不再提供常驻本机账本、旧记录迁移表单或双账本模式。

2.0 是账户模型变更。表结构由 [sql/schema.sql](../sql/schema.sql) 定义，新库只包含一个空的 USD 券商账户。已有数据库由部署者备份并自行适配；应用不会自动迁移旧表、推测账户归属或导入历史资料。检测到不兼容表结构会拒绝初始化，不能将旧 `.db` 直接当作兼容新库。最终字段与核对口径见[数据模型](schema-v2.md)。

部署升级需同步更新服务端和 Python 依赖；APK 更新不会替你升级自托管服务器。Android 使用相同发布密钥覆盖安装，并持久化登录会话、携带会话导出数据。具体构建与验证结果以目标版本 Actions 和 Release 为准。
