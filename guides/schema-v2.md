# 数据模型与计算口径

[返回首页](../README.md) · [使用与部署](使用与部署.md)

2.0 将账户、现金流水与证券交易作为事实来源，余额与配置从明细推导。最终表结构在 [sql/schema.sql](../sql/schema.sql)，不存在手填的总余额、其他资金聚合值或隐藏的第二套账本。

## 账户和现金

| 表 | 保存什么 | 不保存什么 |
|---|---|---|
| `accounts` | 名称、机构类型、资金用途、原币、机构、开户日、归档状态、备注与版本 | 当前余额 |
| `cash_entries` | 账户、日期、类型、有符号原币金额、对手账户、换汇比例、关联标的、撤销关联 | 可覆盖的余额快照 |
| `trades` | 账户、标的、方向、日期、股数、原币价格、手续费、策略标签 | 自动推算的现金结算 |
| `fx_rates` | 基础币、目标币、发布日期、比例、来源和抓取时间 | 用当前汇率改写的历史金额 |
| `settings` | 共享展示币种、时区及其版本 | 资产金额 |
| `allocation_targets` | 证券或账户的目标百分比 | 目标金额或余额 |

账户类型 `kind` 为 `broker`、`bank`、`ewallet`、`provident`、`other`；用途 `purpose` 为 `investing`、`savings`、`emergency`、`spending`、`housing_fund`。两者分别说明账户形态与资金职责。一个账户只有一种原币，多币种机构应拆成子账户。

账户现金余额按截至日期累计 `cash_entries.amount`：

```text
现金余额 = 期初余额 + 入金 + 利息 + 分红 + 转入 − 出金 − 费用 − 转出
```

`balance_open` 表示建账时已确认的存量资金，仅能作为第一笔现金记录；之后按实际发生的流水增减。金额符号与类型必须一致，不允许未来现金记录或产生负余额。当前不建模透支与负债。

现金记录追加保存。单笔错误用关联的反向流水更正，保留原记录；`transfer_cash` 在同一事务中写入转出、转入两条记录，并用 `transfer_group` 关联，跨币种比例来自实际两边金额。不能单独撤销成对流水而留下失衡的一边。

**买卖记录不自动生成现金流水。** Agent 必须根据真实结算另行记入现金支出或收入。证券持仓可能来自更早的记录，不能据此猜测期初现金；不完整的现金明细会直接影响净资产。

## 证券成本与收益

当前证券范围为 USD 美股，必须归属有效的 USD 券商账户。同一标的在不同账户中分别核算成本和可卖股数，不允许用另一个账户的持仓抵消超卖。展示时再按标的汇总。

`strategy` 使用 `dca`、`dip_add`、`rebalance`、`manual`，只说明交易动机，不执行自动交易，也不替代账户用途。

| 指标 | 口径 |
|---|---|
| 买入成本增加 | 股数 × 成交价 + 买入手续费 |
| 卖出净收入 | 股数 × 成交价 − 卖出手续费 |
| 卖出成本扣减 | 卖出股数 × 卖出前移动平均成本 |
| 未实现盈亏 | 当前证券市值 − 剩余持仓成本 |
| 已实现盈亏 | 累计卖出净收入 − 对应已售成本 |
| 累计净投入 | 含手续费的买入支出 − 扣手续费后的卖出收入 |
| 美元累计盈亏 | 当前证券市值 − 累计净投入 |

证券 XIRR 使用实际日期的美元买卖净现金流及期末持仓价值；同日现金流先合并，日数按 365 年化。全部清仓时以最后一笔有效现金流结束；少于 90 天或无法确认唯一可用解时显示原因。支持年化范围为 −99.99% 至 1000%。

现金账户中的利息和分红可以登记，但尚未纳入证券 XIRR，也没有分红再投资调整。XIRR 始终明确为美元口径，不随展示币种改变。

## 净资产与配置

```text
账户估值 = 该账户证券市值 + 该账户现金余额的统一币种等值
净资产 = 所有未归档账户估值之和
```

界面的净资产仅覆盖已记录资产，当前没有负债项。原币余额、折算比例与日期可逐账户核对。任一必需行情或汇率缺失时，总额不使用已知部分冒充完整估值。

目标只保存百分比：

- `scope=securities`：键为标的代码，分母为全部证券持仓市值。
- `scope=net_worth`：键为 `account:<id>`，分母为全部账户估值。

非空目标权重在各自范围内合计 100%；空目标表示未设置。目标金额为相应总额乘目标权重，差额为目标金额减当前金额。市值、成本和股数比例可以分别查看；股数比例只比较数量，不代表资金权重或风险。

## 时间、行情与汇率

最新报价优先新浪，失败后尝试腾讯，保留提供方时间及本次抓取时间。无有效报价时不以旧收盘价替代。历史持仓采用美东交易日、已完成交易时段及当日未复权收盘价。周末、假日和提前收盘由 `XNYS` 日历处理；缺失日断线，尾部停止在最后完整估值。

`fx_rates` 中始终约定 **1 单位 base = rate 单位 quote**。例如假设 `USD/HKD=8`，则 `HKD/USD=0.125`；两者不能交换标签沿用相同数字。这只是方向示例，不是实际报价。

当前转换使用最新 ECB 参考价；历史转换只允许汇率发布日期不晚于估值日，最多沿用 7 个自然日，交叉汇率的两条输入必须来自同一发布日期。ECB 1999 年以前以及早期缺少某币种的日期保持未知，不用后来或当前的汇率填补。当前支持转换 USD、CNY、HKD、EUR；其他账户币种仍保留原币记录，并明确提示没有转换覆盖。

每个历史点保留 `rates`、`rate_dates`、`sources`、`fetched_ats`；比率和百分比仍基于美元证券计算。历史美元盈亏折算为当日等值，不等于按每笔外币现金流重算后的投资回报率。该证券曲线也不等于现金账户完整回放、时间加权净值或账户回撤。

## 初始化与部署责任

新数据库按最终 SQL 初始化，只提供一个空的 USD 券商账户，不附带个人账户、资产金额、示例交易或固定汇率。共享设置默认 USD、`America/New_York`；设备设置可以覆盖展示偏好，美股日历仍固定使用美东时区。

应用没有旧版自动迁移层或导入工具，不执行历史资料中的 SQL。已有数据库由部署者自行备份、适配和核对；不兼容表结构会拒绝初始化。`accufolio-v2` JSON 导出包含业务数据，用于检查和外部处理，不包含登录会话与密钥；完整恢复使用兼容当前结构的 SQLite 备份。

所有资产写入由 Agent 通过 MCP 完成。写权限、预览、幂等键、账户版本与审计用于让变更可核对；浏览器与手机负责查看数据，不提供资产编辑表单。
